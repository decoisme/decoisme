# How I Built a Brutalist Brutalist Portfolio with Next.js 16

Building a portfolio is more than showcasing work—it's about creating an experience that reflects your design philosophy. Here's how I built mine with **brutalist design principles** and **premium interactions**.

## The Design Philosophy

Brutalism in web design isn't about being ugly—it's about being **honest, raw, and functional**. My goals were:

- **Zero unnecessary decoration** - No gradients, no shadows, no blur
- **Pure monochrome** - Black (#000000) and white (#FFFFFF) only
- **1px borders** - Sharp, clean separations
- **Instant state changes** - No slow transitions (duration-0)
- **Terminal aesthetic** - Monospace fonts, system labels

But I also wanted **premium feel**:
- Smooth spring animations
- Interactive magnetic buttons
- Engaging text reveals
- Progress feedback

## Key Features Implemented

### 1. Magnetic Cursor Effect

Buttons subtly pull towards the cursor when hovering nearby, creating an interactive feel.

\`\`\`typescript
// components/ui/magnetic-button.tsx
const handleMouseMove = (e: React.MouseEvent) => {
  const rect = ref.current.getBoundingClientRect();
  const centerX = rect.left + rect.width / 2;
  const centerY = rect.top + rect.height / 2;
  
  const distanceX = e.clientX - centerX;
  const distanceY = e.clientY - centerY;
  
  setPosition({
    x: distanceX * strength,
    y: distanceY * strength,
  });
};
\`\`\`

**Result**: Buttons feel alive and responsive.

### 2. Text Reveal Animation

Headers reveal letter-by-letter, creating a typewriter effect perfect for the terminal aesthetic.

\`\`\`typescript
// Stagger children with 30ms delay
const container = {
  hidden: { opacity: 0 },
  visible: {
    opacity: 1,
    transition: { 
      staggerChildren: 0.03,
      delayChildren: 0.5,
    },
  },
};
\`\`\`

**Result**: Engaging header entrances that match brutalist aesthetic.

### 3. Scroll Progress Indicator

A 1px line at the top that grows as you scroll—minimalist but informative.

\`\`\`typescript
const { scrollYProgress } = useScroll();
const scaleX = useSpring(scrollYProgress, {
  stiffness: 100,
  damping: 30,
});

return (
  <motion.div
    className="fixed top-0 left-0 right-0 h-[1px] bg-black"
    style={{ scaleX }}
  />
);
\`\`\`

**Result**: Users always know their progress through the page.

### 4. View Transition API

Native browser API for smooth page transitions with zero JavaScript cost.

\`\`\`css
@view-transition {
  navigation: auto;
}

::view-transition-old(root) {
  animation: fade-out 0.3s ease-out;
}
\`\`\`

**Result**: Professional polish at zero cost.

## Lessons Learned

### 1. Brutalism + Premium Can Coexist
You don't have to choose between minimalist aesthetics and engaging interactions. The key is **subtle motion** that enhances rather than distracts.

### 2. Performance Matters More Than Features
I removed several "cool" features that hurt performance. A fast, responsive site beats a feature-rich slow one every time.

### 3. Accessibility Is Non-Negotiable
All animations respect `prefers-reduced-motion`. Keyboard navigation works everywhere. Screen readers can access all content.

### 4. Mobile First, Always
Every animation, every interaction was tested on mobile first. If it didn't work on a phone, it didn't ship.

## Technical Challenges & Solutions

### Challenge 1: React Hooks Violations
**Problem**: Conditional `useTransform` calls inside custom hooks broke Rules of Hooks.

**Solution**: Use simple `initial` + `whileInView` props instead of complex custom hooks.

\`\`\`typescript
// ❌ Wrong - Conditional hooks
if (isMounted) {
  x = useTransform(scrollYProgress, [0, 1], [-30, 0]);
}

// ✅ Right - Direct props
<motion.div
  initial={{ opacity: 0, x: -30 }}
  whileInView={{ opacity: 1, x: 0 }}
/>
\`\`\`

### Challenge 2: Hydration Errors
**Problem**: Server-rendered HTML didn't match client on first render.

**Solution**: Ensure animations trigger only after mount, use CSS for instant states.

### Challenge 3: Mobile Performance
**Problem**: Spring animations janky on mid-range phones.

**Solution**: Reduce spring stiffness on mobile, use simpler easing.

## Conclusion

Building this portfolio taught me that **constraints breed creativity**. By limiting myself to pure black and white, no shadows, and 1px borders, I was forced to focus on **motion, timing, and interaction design**.

The result is a portfolio that:
- Loads in under 1 second
- Works perfectly on every device
- Is fully accessible
- Stands out in a sea of gradient-heavy portfolios
- Converts visitors into clients

### Key Takeaways
1. **Brutalism works** - if done with intention
2. **Performance is a feature** - not an afterthought
3. **Subtle motion** > flashy animations
4. **Accessibility** = better UX for everyone
5. **Test on real devices** - emulators lie
